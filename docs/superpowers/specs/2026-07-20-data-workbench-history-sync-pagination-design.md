# 数据查看持久化与日线加载修复设计

## 背景

2026-07-20 的真实运行记录显示，“日常更新”从前端提交了默认自定义股票 `000001.SZ`。组合任务中的日线步骤因此只同步了一只股票，贵州茅台仍停留在 2026-07-14。与此同时，数据查看页查询贵州茅台 2024-07-20 至 2026-07-20 的日线时，本地 Parquet 有 479 条，但 `/api/data/klines` 默认分页只返回最新 100 条。页面的“最近查看”则是五只硬编码股票，每次加载都会重置。

## 目标行为

1. “最近查看”只包含用户主动搜索或切换过的股票，按最近访问时间倒序保存最多 10 只；刷新页面或重启浏览器后仍保留。
2. “日常更新”页面默认选择“全市场”，提交 `datasync` 时不携带默认股票列表。
3. K 线接口返回明确的 `page`、`page_size`、`total_pages` 元数据。
4. 日线首次加载最近 250 条；用户把时间轴拖到左侧时，页面自动请求下一页并合并更早数据，直到覆盖所选日期范围。
5. 股票、周期或日期范围变化时，旧分页状态失效并从第一页重新加载；重复行按交易时间去重。
6. 修复后执行一次全市场日线增量同步，并验证贵州茅台到达 QMT 当前可用最新交易日。

## 设计

### 最近查看

新增 `frontend/src/views/DataManage/recentStocks.ts`，负责版本化 localStorage 读写、运行时校验、去重和最多 10 条裁剪。键名为 `gaoshou:data-workbench:recent-stocks:v1`。存储失败或损坏时返回空数组，不恢复任何硬编码股票。

页面初始化时从该模块读取记录；只有 `handleStockChange()` 和点击最近记录触发的显式选择会写入。默认打开贵州茅台仅用于页面初始内容，不自动污染用户历史。

### 日常更新默认范围

`SyncPanel.vue` 的 `stockScope` 初始值从 `custom` 改为 `all`。用户仍可主动切换到自定义股票；`basePayload()` 保持现有契约，在全市场模式下将 `symbols` 留空。

### K 线分页与拖动加载

后端 `/api/data/klines` 保留分页查询，响应补充 `page`、`page_size`、`total_pages`。前端 API 类型同步这些字段。

数据查看页为日线使用 250 条分页，分钟线维持 1000 条上限。`KlineChart.vue` 订阅 lightweight-charts 的可见逻辑区间；当左边界接近最早已加载数据时发出 `request-older`。父页面串行加载下一页，通过 `symbol + period + date range` 请求版本防止切换后的旧响应写回，并按 `datetime` 合并去重。

### 错误处理

- localStorage 内容不是合法数组或股票代码为空时忽略该条目。
- 历史页请求失败时保留当前图表数据，并允许下一次拖动重试。
- 已加载完全部页、正在请求或查询版本已变化时不再追加。

## 验证

- 前端单元测试覆盖 localStorage 恢复、最多 10 只、去重置顶、损坏数据和无硬编码默认值。
- 组件/源码契约测试覆盖全市场默认值、分页参数、左拖加载和分页重置。
- 后端 API 测试覆盖分页元数据。
- 真实接口验证贵州茅台两年范围总数大于 100，并能通过第二页取得更早日期。
- 全市场日线增量同步后直接查询 Parquet 与 API 的贵州茅台最新日期。
