# 利通电子与澜起科技日内做 T 策略服务设计

日期：2026-07-18

## 1. 目标

在 GaoshouPlatform 中新增一套面向既有 A 股底仓的日内做 T 服务，固定支持：

- 利通电子（`603629.SH`）
- 澜起科技（`688008.SH`）

服务以降低持仓成本为第一目标，提供分钟级历史回测和实时模拟盘信号。每个交易日结束时，持股数量必须恢复到当日开盘底仓数量。真实委托不在本期范围内，任何接口都不得绕过现有 V1 实盘审批与下单护栏。

## 2. 已确认约束

- 数据源使用本地 `klines_minute` Parquet，通过 `get_market_data_store()` 读取。
- 两只股票的本地分钟数据分别覆盖 2018-12-24 和 2019-07-22 至 2026-07-14。
- 支持正 T（先买后卖）和倒 T（先卖后买）。
- 当日累计卖出数量不得超过开盘可用底仓，今日买入数量不增加今日可卖数量。
- 单次交易默认最多使用开盘底仓的 25%，每日每只股票最多完成 2 组交易。
- 14:40 后停止开仓，14:49 生成强制恢复指令，以下一分钟开盘价模拟成交。
- 利通电子买入按 100 股整数倍；澜起科技限价申报最少 200 股，超过 200 股后允许按 1 股递增。卖出不足最低数量的余额仅允许一次性清仓，但做 T 数量默认不会制造零碎余额。
- 回测结果必须把底仓市值涨跌与做 T 增量损益分开。

规则依据：

- 上海证券交易所《交易规则（2026 年修订）》3.1.4、3.3.8、6.7。
- <https://www.sse.com.cn/lawandrules/sselawsrules2025/stocks/exchange/c/c_20260424_10816482.shtml>

## 3. 非目标

- 不做券商席位级低延迟交易或 Level-2 逐笔撮合复现。
- 不承诺复现特定券商的私有模型参数或收益。
- 不自动提交真实委托。
- 不扩展到任意股票池、ETF 或融资融券卖空。
- 不将普通 A 股当成真正可当日回转的证券。

## 4. 总体架构

新增独立模块，不继续扩展当前为两只其他股票硬编码的 `GridTradingService`。

### 4.1 核心策略模块

`backend/app/services/intraday_t_strategy.py`

- 纯计算组件，不访问数据库、网络或全局状态。
- 接收标准化分钟 bar、交易参数和单日账户状态。
- 输出特征快照、信号、状态迁移和订单意图。
- 同一套实现供历史回测和模拟盘使用，避免两套策略逻辑漂移。

### 4.2 历史回测模块

`backend/app/services/intraday_t_backtest.py`

- 通过 MarketDataStore 加载两只股票分钟线。
- 按交易日和股票独立回放，再合并组合权益曲线。
- 信号由当前分钟收盘数据产生，最早在下一分钟开盘成交。
- 模拟佣金、最低佣金、印花税、过户费、滑点、成交量上限和涨跌停不可成交。
- 生成逐笔配对、逐日指标、股票级指标、组合指标和被动持有基准。

### 4.3 模拟盘服务

`backend/app/services/intraday_t_paper.py`

- 启动时从 QMT 账户快照读取目标股票持仓和可卖数量，也允许测试环境传入手工快照。
- 优先用本地当日分钟历史预热窗口，之后把 QMT 实时报价按自然分钟增量聚合为标准 bar；如果本地当日数据不可用，则必须积累满 `warmup_minutes` 后才能生成信号，不得用不完整窗口静默降级。
- 只执行模拟成交，写入独立的模拟会话和交易记录。
- 后台 runner 默认每 30 秒评估一次；同一分钟重复评估必须幂等。
- 服务重启后从 SQLite 恢复当日会话和未配对交易。

### 4.4 API 与前端

- 新路由前缀：`/api/intraday-t`。
- 新页面：`/trade/intraday-t`，导航名“日内做 T”。
- 页面聚焦两只标的，提供回测、模拟盘控制、信号时间线、配对交易、底仓恢复状态和绩效。

## 5. 信号模型

### 5.1 特征

每只股票每日独立计算：

1. `session_vwap`：当日截至当前分钟的成交量加权平均价。
2. `deviation`：`close / session_vwap - 1`。
3. `deviation_zscore`：偏离值除以最近 `vol_window` 分钟偏离标准差。
4. `ema_fast`、`ema_slow`：短、长周期指数均线。
5. `vwap_slope`：最近 `slope_window` 分钟 VWAP 线性斜率。
6. `volume_ratio`：当前 5 分钟均量相对最近 30 分钟均量。
7. `estimated_edge_bps`：当前价格回归 VWAP 的理论空间。

标准差设置价格相关下限，避免平静时段被极小分母放大。

### 5.2 入场

默认参数：

| 参数 | 默认值 |
|---|---:|
| `warmup_minutes` | 30 |
| `vol_window` | 30 |
| `ema_fast` | 10 |
| `ema_slow` | 30 |
| `entry_zscore` | 1.75 |
| `exit_zscore` | 0.25 |
| `stop_zscore` | 3.0 |
| `max_trade_fraction` | 0.25 |
| `max_round_trips` | 2 |
| `cooldown_minutes` | 10 |
| `min_edge_buffer_bps` | 12 |
| `max_daily_loss_bps` | 45 |

正 T 入场要求：

- `zscore <= -entry_zscore`；
- 当前收盘价高于上一分钟收盘价，形成止跌确认；
- 预期回归空间大于完整交易成本与安全边际；
- 未检测到向下单边趋势；
- 当前成交量有效且未触及跌停附近不可成交区。

倒 T 入场要求对称：

- `zscore >= entry_zscore`；
- 当前收盘价低于上一分钟收盘价，形成冲高衰竭确认；
- 未检测到向上单边趋势；
- 可卖底仓和预计回补资金充足。

### 5.3 趋势过滤

当以下条件同时成立时认为存在单边趋势，禁止逆势均值回归开仓：

- `ema_fast` 与 `ema_slow` 的相对距离超过参数阈值；
- 两条均线方向一致；
- VWAP 斜率同向；
- 量比高于趋势确认阈值。

该过滤器只阻止新开仓，不阻止已有交易恢复底仓。

### 5.4 退出与风险退出

- 正常退出：偏离回到 `exit_zscore` 内，或达到参数化净利润目标。
- 止损退出：偏离扩大到 `stop_zscore`，或单组净亏损超过限额。
- 时间退出：上午未平仓交易在 11:29 前恢复；下午 14:49 生成恢复指令。
- 日内锁定：累计净亏损达到 `max_daily_loss_bps` 后，不再开仓。
- 恢复优先级高于所有信号和利润条件。

## 6. 状态机与 T+1 记账

每只股票每天保存：

- `opening_quantity`
- `opening_available`
- `current_quantity`
- `sellable_remaining`
- `cash`
- `active_pair`
- `completed_pairs`
- `realized_t_pnl`
- `fees`
- `locked_reason`

状态：

- `READY`：允许寻找入场。
- `POSITIVE_T_OPEN`：已额外买入，等待卖出相同数量的开盘可卖底仓。
- `REVERSE_T_OPEN`：已卖出部分开盘底仓，等待买回相同数量。
- `FORCE_RESTORE`：只允许提交恢复方向订单。
- `RESTORED`：当前数量等于开盘数量且无活动配对。
- `LOCKED`：达到风险限额，不再开仓；若仓位未恢复仍继续恢复。

成交驱动状态迁移。订单生成不改变仓位，只有模拟成交后才更新数量、现金和可卖数量。买入永远不增加 `sellable_remaining`；卖出会减少它。

## 7. 成交与费用模型

### 7.1 无未来数据

- 在分钟 `t` 收盘计算信号。
- 市价模拟订单在分钟 `t+1` 的开盘成交并叠加方向性滑点。
- 限价模拟订单只有在下一分钟高低价穿越限价时成交。
- 不能用触发信号的同一分钟收盘价成交。

### 7.2 成交限制

- 单笔成交不超过下一分钟成交量的 `volume_limit_pct`。
- 停牌、零成交量、无有效价格时拒绝成交。
- 涨停附近买单、跌停附近卖单按不可成交处理。
- 价格限制优先读取本地 `stock_limit_prices`；缺失时使用前收盘价与板块规则估算，并在结果中标记估算来源。

### 7.3 成本

所有成本从 API/前端参数传入，默认沿用平台统一口径：

- 佣金率
- 最低佣金
- 卖出印花税
- 过户费
- 滑点

做 T 入场前按两腿总成本估算最低所需价差。

## 8. 回测输出

组合级：

- 做 T 毛收益、净收益和总成本
- 相对被动持有的增量收益
- 成本降低额与每股成本降低额
- 完成配对数、胜率、盈亏比
- 最大单日做 T 亏损、最大回撤
- 日终底仓恢复率与恢复失败次数
- 正 T/倒 T 分方向绩效

股票级输出同样指标，并包含参数、数据覆盖、拒单原因统计和逐日结果。

逐笔记录必须保存两腿时间、价格、数量、方向、费用、毛/净损益、最大有利/不利波动和退出原因。

## 9. API 契约

### 查询

- `GET /api/intraday-t/capabilities`
- `GET /api/intraday-t/data-coverage`
- `GET /api/intraday-t/paper/status`
- `GET /api/intraday-t/paper/trades`

### 回测

- `POST /api/intraday-t/backtest`

请求包含日期、初始资金、股票权重或底仓数量、策略参数及成本参数。响应包含完整指标、曲线、逐日和逐笔结果。

### 模拟盘

- `POST /api/intraday-t/paper/start`
- `POST /api/intraday-t/paper/evaluate`
- `POST /api/intraday-t/paper/stop`
- `POST /api/intraday-t/paper/reset`

`start` 支持从 QMT 读取底仓或传入手工测试快照。所有写操作带请求幂等键。`reset` 仅允许重置已停止且无未恢复配对的会话。

## 10. 持久化

新增两张 SQLite 表：

- `intraday_t_sessions`：交易日、参数、账户基线、每只股票当前状态、runner 状态和最后评估分钟。
- `intraday_t_trades`：订单意图、成交、配对、费用、损益、退出原因和幂等键。

启动时通过现有 SQLAlchemy 初始化流程建表。数据库模型纳入 `app.db.models` 导出，确保元数据可发现。

## 11. 前端

新页面采用三段式工作台：

1. 顶部状态带：数据覆盖、QMT 行情、模拟 runner、日终恢复状态。
2. 主区：两只股票固定行，展示现价、VWAP、Z-score、趋势状态、开盘/当前/可卖数量、活动配对和下一动作。
3. 下区标签页：历史回测、配对交易、每日绩效、参数。

回测表单提供日期、初始资金、两只股票权重/底仓数量、稳健参数和成本。页面不出现真实下单按钮。

## 12. 错误处理

- 数据缺口、QMT 不可用、账户无目标底仓、底仓小于最小交易量、恢复失败均返回明确错误码和中文说明。
- 不捕获后静默使用虚构价格、虚构持仓或零成本。
- 单只股票失败不污染另一只股票状态，但组合响应必须显示降级状态。
- runner 异常时停止开新仓；若存在活动配对，继续尝试恢复并持续告警。

## 14. 完成标准

- 两只目标股票可独立或组合运行分钟回测。
- 回测严格遵守下一分钟成交、T+1 可卖约束和日终恢复。
- 模拟服务可从账户底仓启动、生成信号、记录模拟配对并在重启后恢复。
- 页面可完成回测和模拟盘操作，且无真实下单入口。
- 后端定向测试、AKQuant 集成测试、前端测试与构建通过。
- 后端与前端按 prod 端口重启，健康检查通过。
